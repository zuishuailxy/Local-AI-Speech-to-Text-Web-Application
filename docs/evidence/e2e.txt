## 测试设计

- `e2e` 标记，默认 `pytest -q` 不执行。
- 模块级 fixture 启动真实 uvicorn（随机端口），注入 `FakeTranscriber(text="E2E browser transcription result.")`。
- Playwright Chromium/Chrome 启动参数：
  - `--use-fake-ui-for-media-stream`
  - `--use-fake-device-for-media-stream`
  - `--use-file-for-fake-audio-capture=samples/english.wav`
- 上下文授予 `microphone` 权限。
- 覆盖三项：
  1. 页面加载：标题、idle、语言默认 zh、Start 可用、Upload 禁用、无相关控制台错误。
  2. 文件上传：选 en → `samples/english.wav` → Upload → success；检查文本、语言、9.0 s 时长、Copy 可用、音频预览可见。
  3. 假麦克风录音：Start → recording → 录制 ≥1.2 s → Stop → success；检查 `lastRecording` 为 `audio/webm`、大小 >1000 bytes、时长 ≥1 s；结果字段与语言正确。

## Windows CI

`.github/workflows/windows.yml` 新增：

```yaml
- name: Install browser E2E dependencies
  run: |
    python -m pip install -r requirements-e2e.txt
    python -m playwright install chromium

- name: Run browser E2E
  run: python -m pytest -q -m e2e
```

`requirements-e2e.txt` 不进入运行依赖，只固定 `playwright==1.64.1`。CI 使用自带 Chromium，不设置 `PLAYWRIGHT_CHANNEL`。

### CI 结果

首次加入 e2e 步骤的 run `40633226986` 失败在默认 `Run tests`：

```text
ModuleNotFoundError: No module named 'playwright'
```

原因：默认 CI 只安装 `requirements.txt`，但 pytest 收集 `tests/e2e/test_browser.py` 时会先执行模块导入，即使 3 个用例会被 `-m "not e2e"` 排除。

修复分两步：

1. 先在 e2e 模块加 `pytest.importorskip("playwright.sync_api")`，让默认 CI 不再失败。
2. 随后把 Playwright 导入移到 `browser` fixture 内延迟执行，默认套件即使没装 Playwright 也能正常收集并 deselect。

第二次 run `40633358118`：

```text
Run tests                      success
Install browser E2E dependencies success
Run browser E2E                success
```

`windows-latest` 上实际跑通 3 项浏览器 E2E；这仍不是 Windows 11 真实桌面/麦克风验证。

## 隐私与边界

- 使用 Chromium 假麦克风与固定 WAV，不是真实麦克风；真实麦克风验证仍属 T6.1/T6.2。
- 使用 `FakeTranscriber`，不证明真实模型准确率；真实模型由 T5.2/T5.3 覆盖。
- 页面加载只忽略 favicon 404，其他 console error / pageerror 均视为失败。
- 截图由 `E2E_SCREENSHOT_DIR` 控制，默认不写文件。
- 未覆盖 60 秒自动停止、权限拒绝、Edge；分别由 T4.3/T4.4 单测、T6.5、T6.11 覆盖。
