# 录音计时 / 音频时长 / 处理计时 / 处理耗时 文案对齐

- 日期：2026-10-28
- 分支：`optimization/post-delivery`
- 问题：页面“录音时长”与结果“音频时长”不一致；“识别耗时”与“处理耗时”精度/语义不一致

## 原因

- 录音计时是浏览器墙钟（MediaRecorder/JS 计时），用于 60 s 上限；服务端音频时长来自实际解码样本数，差 0.1–0.2 s 属于正常。
- 处理计时是请求期间的前端实时计时；处理耗时是服务端 `processing_seconds`，包含解码/模型/推理，可能有几十毫秒差异，且原先分别显示 1 位/2 位小数。

## 修改

- 麦克风区：
  - `录音时长` → `录音计时（墙钟）`
  - `识别耗时` → `处理计时（实时）`
- 结果区：
  - `音频时长` → `音频时长（服务端）`
  - `处理耗时` → `处理耗时（服务端）`
- 前端所有实时/最终处理计时统一 `toFixed(2)`。
- 增加提示：录音计时为浏览器墙钟，音频时长/处理耗时以服务端为准，可能有 0.1–0.2 s 差异。

## 验证

- 静态测试断言以上四个标签和 `toFixed(2)`。
- 全量测试通过。
- 不改变服务端四字段，不改变计时/上限逻辑。
- 截图 `realtime-latency.png` 为改标签前页面；当前文案已更新为“录音计时（墙钟）/处理计时（实时）/音频时长（服务端）/处理耗时（服务端）”。
